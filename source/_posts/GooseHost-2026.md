# 相伴GooseHost —— 2026年度总结

## 关于

GooseHost 是 ~~[GooseCode](https://goosecode.surge.sh/)旗下的~~ 一个开源、轻量、免费、可自部署的静态心网站托管平台。GooseHost 收益于 Cloudflare 全球网络，可实现全球访问。GooseHost 为新手网页开发提供了更便捷、快速的托管，其命令行工具可集成于 Vibe Coding 流水线。GooseHost 用每个位置都充满了故事，那么，来了解一下？

## 前世今生

GooseHost 由 Freewebweb 衍化而来，但两者架构并不相同（我放弃Freewebweb 就是因为他史一样的底层），并且，在 GooseHost 诞生之前，我便预测到，一旦Freewebweb 网站数量增多，可能它就会直接停摆（应该是管理后台停摆），嗯，在 GooseHost上线不久，这件事便发生了 —— Freewebweb 网站数量达到了99，管理后台打不开了。后台要一口气读99条数据，每条都是一个完整的网页。虽然我当时小修了一下，但这无疑是杯水车薪（没啥卵用）... 后来便停站了。值得一提的是，LongMoon 于今年年底复活了Freewebweb，并声称重构其底层，期待它的表现！

## 广场

我在 B 站上发布 GooseHost 的视频后，硬生生为我增加了 30 多个用户，所以我就想做个社区，让这些用户都能互相看见，就做出了广场，**但是**，就在广场发布的 48 小时后，GooseHost 赖以生存的域名 `goose.gs.cn` 被赞助商撤走，至于为啥......~~咱也不敢说,咱也不敢问 ^_^~~，导致用户活跃数量急速下降，只有骨灰级用户知道我换回了曾经（也是现在）的 `goose.cc.cd` 域名（在此感谢 DNSHE 帮找收回了被盗的 DNSHE 账号）于是，现在的社区也不太活跃，我也没有对它做出更新，一直保持着出厂状态。

## 后端发生的事儿

是的，你应该知道这回事，在 `cc.cd` 域名恢复正常运转的 72 小时后，GooseHost 所有用户消失不见（对，包括我自己）。之前我一直没讲过这件事故的原因，现在我借此机会说一下。GooseHost 在发布之初，为了防止有些人注册完就跑，我在后端代码加上了：3小时内该用户未创建网站，注销此用户。结果就是这段代码在那天卡了返回了个 null，于是负责删除用户的代码就开始忠实地执行 `null` —— 清空所有用户。于是我抄起 Deepseek 着急忙慌地去了 Supabase 后台，在 logs 中恢复了用户数据，但密码是找不回来了。哎，所幸的是，当时负责删除用户的代码只删用户，不删数据，数据便被意外地保留了下来......

> 哎有人跟我说是先删的用户后域名没了呢？记不住了。

这件事也是给了我一个教训，我在修好后便创建了一个 Github 私人仓库，负责同步 GooseHost 用户数据和站点数据，作为容灾备份。

> 只删人不删数据？
> 
> - 是的，我在这里讲一下 GooseHost 开发期间的趣事：哎，放到后面讲吧，嘻。

## CLI's story

CLI 是物啥，所以应该是：The story of the CLI of the GooseHost。额（不要在我这学英语！我语法很拉的！）是的，冷冰冰的 CLI 也有它的故事。

### Python

早期的 GooseHost CLI 是用 Python 写的，并且发布在了 pypi 上（现已停止维护）只需要 `pip install goosehost-cli` 。但这依赖于 python，那没安装 python 的电脑......（可以说几乎没有，CLI 用于 Vibe Coding 流水线、OpenClaw、Agent，真要是真人用，用电脑里怎么能连 python 都没有？）嗯，所以我还是采纳了 Deepseek 的建议：使用 go 重写。

### Go

新版基于 Go 甚至是由网页版D老师写的，还有 action 工作流（哎我就这破win7 能干什么鸡毛啊）。加起就写了 3 个文件，那老 python，噼里啪啦一大堆 build，轮子......

### 放弃副站？

在 CLI 1.1 版本，你会看到放弃对 GooseHost PHP 的支持，原因就是 Infinityfree 的限制，只能用浏览器。其实如果还用 python 是可以解决这问题的：在Pypi上有 Infinity 的官方库，直接可以模拟真实浏览器 JS 计算网页，只要把官方库的内置 request 库模拟成 C（什么来自，也是模拟浏览器）库，就可以调用了，但实在太麻烦了。哎，增加代码量（话说回来了，几个人用啊？我现在 skilhub 上的 GooseHost skill 下载量都 400 了，我有几个用户？）。

## 开发期间趣事

GooseHost 早期（也就是底层）是 OpenClaw（混元T1）也就是元宝 bot写的。但是元宝 bot 额度很少，也就够聊个天，而且他不显示工具调用，导致视觉上说话跟王八似的。然后聊着聊着：`Your billing run out......`，于是我在元宝里 ~~~借鉴~~~ 了个 bot 过来，所以我有了两个 bot，一个用完另一个，这就导致两个 bot 互相不知道上下文（我当时还不知道有 Memory.md 这东西）。
**于是就出现了个搞笑的现象**：html 站点和markdown 站点的架构不一样，乱成一锅粥（屎一样的底层）。而且我实际测试报告问题后，AI 不会觉得他写的不对，也不会读文档，就会打补丁，补的跟杜甫的棉被似的。（嗯，自动删除用户就是那个时候埋下的）。
**还有一件事**：GooseHost 源码曾经丢过。这不好笑 ~~不儿，别笑了~~ 那天 bot 打死就说不出来话了，怎么修都不行，只能重置，但是源码还在那里。嗯，但我还是把它重置了。然后我又阴差阳错找到了 bot 本次变更之前的上一个版本原代码我比当时线上多了一次更新。结果就是网页版D老师自告奋勇把最新的恢复了回来......
**文件删不掉**：你看 GooseHost 当前 200 多站点，但桶里躺 700 多文件，这不是 project项目撑的，只删站点后桶文件压根没删，~~跟某绿泡泡似的~~。追根溯源一下：我告诉 OpenClaw 删除站点失败，结果这货直接在删桶文件那里加了个出错静默跳过.....
